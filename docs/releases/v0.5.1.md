# SkillTape 0.5.1

The release smoke now checks the actual localized title, matching API/UI build identities and reachable built assets. The failed v0.5.0 tag and its build records remain unchanged; no public v0.5.0 Release was published.

This release brings the CLI, read-only Console and Apple Silicon application to the same source revision.

- The application opens saved Capture evidence first, with workspace guidance; the separate quantity worksheet remains accessible.
- Open a retained Capture, inspect its recording coverage, continue with a deterministic local starter, review permissions and verify the resulting package with explicit assertions.
- Review saved Receipts, compare attempts, inspect failed checks and export only a matching successful delivery. Quantity calculations remain a separate local worksheet, not a verified Receipt.
- Large Receipt sections display 100 rows per page. JSON previews have traversal and text limits before serialization. Every retained row remains reachable and failure totals stay visible.
- Tape event inspection shares the existing two-job admission limit and runs off the async HTTP thread. Capture source matching hashes the full bounded normalized stream without holding every event and a second full JSON copy.
- Archives include the optional stopped-workspace backup/check/new-directory recovery tool and its operating instructions. Python 3 is needed only for that operator tool.
- CLI archives and installed Consoles retain the project license and tracked third-party notices under `console/licenses`; the native app retains its runtime notices as before.
- Application-manifest inspection reads and hashes bytes without executing selected apps; known checkout build outputs are the only executable identity sources.
- New releases require successful matching main checks and refuse to overwrite an existing Release. Each CLI/API/UI archive carries build identity, checksums, SBOM and provenance.

The macOS Apple Silicon ZIP contains a relocatable application and uses ad-hoc signing. It is not Apple notarized. macOS compatibility is recorded from the actual binary deployment targets in its source manifest. Windows supports package preparation and read-only inspection; execution and verification still require a supported macOS/Linux system sandbox. No permission or network default is expanded.

Existing Releases, Tapes, successful Receipts, histories and user workspaces remain intact. Installing this version does not automatically migrate, execute or upload them.
